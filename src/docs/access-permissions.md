# 用户登录态、实名状态对应的读写权限说明

本文说明访问本站用户服务时，不同登录态与实名状态对应的能力边界。接口细节以实际后端为准。

## 状态定义

| 状态 | 判定 | 说明 |
|---|---|---|
| 匿名 | 无有效 Access Token | 未登录访客 |
| 已登录未实名 | 已登录且 `verified=false` | 常见于仅完成 Gitee / GitHub 授权、尚未绑定手机号的用户 |
| 已登录已实名 | 已登录且 `verified=true` | 手机号登录用户，或 OAuth 用户完成绑手机后 |

- 未登录访问需登录接口：通常 **HTTP 401**（`NEED_LOGIN`）
- 未实名访问需实名接口：通常 **HTTP 403**（`NEED_VERIFY`）

## 能力对照

| 能力 | 匿名 | 已登录未实名 | 已登录已实名 |
|---|---|---|---|
| 浏览首页、支持文档 | 可读 | 可读 | 可读 |
| 发送登录短信 / 短信登录 | 可写 | 可写 | 可写 |
| 获取 OAuth 授权地址 / 完成回调登录 | 可写 | 可写 | 可写 |
| 刷新 Token / 登出 | 按 Cookie 处理 | 可写 | 可写 |
| 查看个人资料（`/user/me`） | 否 | 可读 | 可读 |
| 绑定手机号（发码 / 提交） | 否 | 可写（OAuth 渠道） | 一般无需再绑 |
| 修改昵称 | 否 | 否 | 可写 |
| 代理授权（查询 / 发起 / 接受 / 撤销） | 否 | 可读写 | 可读写 |
| 进入账户管理页（前端） | 仅提示登录 | 可进入 | 可进入 |

## 补充说明

1. **手机号渠道**账号登录后一般为已实名，前端不再提供「绑手机」入口。
2. **OAuth 渠道**未绑手机时为未实名：可管理代理关系、查看资料，但改昵称前须先完成绑手机。
3. 绑手机成功后服务端会重新签发 Token（`verified=true`），前端需替换本地 Access Token 后再调用需实名接口。
4. 「可读 / 可写」针对本站用户服务 API；具体业务项目（如结构导图等）可能另有权限规则。
